# 阿里 Java 单元测试强制规约

离线规则集：整理自《阿里巴巴 Java 开发手册》`1.3.0` 版的 `【强制】` 条款，并做了规约化转述。使用本 skill 不需要访问任何外部文件。

## 强制规则

- 好的单元测试必须遵守 AIR 原则：自动化、独立性、可重复执行。
- 单元测试必须全自动执行，不得依赖人工交互。
- 单元测试之间必须保持独立，不得依赖执行顺序。
- 单元测试必须可重复执行，不得受到外部环境偶然状态影响。
- 单元测试粒度要足够小，最多到类级别，一般应到方法级别。
- 核心业务、核心应用、核心模块的增量代码必须确保单元测试通过。
- 单元测试代码必须写在 `src/test/java`，不得写在业务代码目录。

## 使用时的最低检查

- 新增或修改核心逻辑时，必须补充或运行相关测试。
- 如果代码依赖数据库、缓存、时间、随机数、网络或外部服务，必须隔离这些不稳定因素。
- 如果无法运行测试，最终答复必须说明原因、影响范围和残余风险。
