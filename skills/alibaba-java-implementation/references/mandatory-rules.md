# 阿里 Java 编码实现强制规约

离线规则集：整理自《阿里巴巴 Java 开发手册》`1.3.0` 版的 `【强制】` 条款，并做了规约化转述。使用本 skill 不需要访问任何外部文件。

## 命名

- 命名不得以下划线或美元符号开头或结尾。
- 命名不得使用中文，不得使用拼音和英文混写；纯拼音也应避免。
- 类名使用 `UpperCamelCase`，但 `DO`、`BO`、`DTO`、`VO`、`AO` 等后缀保持全大写。
- 方法名、参数名、成员变量、局部变量使用 `lowerCamelCase`。
- 常量全大写，单词之间用下划线分隔，名称必须表达完整语义。
- 抽象类以 `Abstract` 或 `Base` 开头；异常类以 `Exception` 结尾；测试类以被测类名开头并以 `Test` 结尾。
- 数组类型的中括号属于类型本身，使用 `String[] args`，不要写成 `String args[]`。
- POJO 布尔属性不要加 `is` 前缀，避免框架解析错误。
- 包名全部小写，点分隔的每段只表达一个自然语义；包名使用单数形式。
- 禁止随意缩写，尤其是会造成望文不知义的缩写。

## 常量

- 代码中不得直接出现魔法值，应定义有语义的常量。
- `long` 或 `Long` 赋值时使用大写 `L`，不得使用小写 `l`。

## 代码格式

- 非空代码块的大括号遵循：左大括号前不换行，左大括号后换行，右大括号前换行；右大括号后如有 `else` 等不换行，否则换行。空块可写成 `{}`。
- 左右小括号与内部字符之间不加空格。
- `if`、`for`、`while`、`switch`、`do` 等关键字与左括号之间必须有一个空格。
- 二目、三目运算符左右两侧都必须有一个空格。
- 使用 4 个空格缩进，禁止使用 tab 字符。
- 单行注释 `//` 与注释内容之间有且仅有一个空格。
- 单行字符数不得超过 120；超出时按运算符、点号、逗号等可读边界换行。
- 方法参数在定义和传入时，多个参数的逗号后必须有空格。
- 文件编码使用 UTF-8，换行符使用 Unix 格式。

## OOP

- 避免通过对象引用访问本类静态变量或静态方法。
- 所有覆写方法必须加 `@Override`。
- 只有参数类型相同且业务含义相同时，才使用可变参数；避免使用 `Object` 可变参数。
- 已被外部调用或二方库依赖的接口，不允许随意修改方法签名。
- 不得使用过时类或过时方法。
- 调用 `equals` 时使用常量或确定非空对象作为调用方，避免空指针。
- 包装类型对象之间的值比较必须使用 `equals`，不得使用 `==`。
- 所有 POJO 属性必须使用包装类型。
- RPC 方法参数和返回值必须使用包装类型。
- 定义 DO、DTO、VO 等 POJO 时，不要给属性设默认值。
- 序列化类新增属性时，不要修改 `serialVersionUID`；完全不兼容升级时才修改。
- 构造方法中不得加入业务逻辑；初始化逻辑放到 `init` 类方法或等价初始化流程。
- POJO 类必须实现 `toString`；继承场景需要包含父类字段。

## 集合

- `hashCode` 和 `equals` 必须成对遵守：重写 `equals` 必须重写 `hashCode`；作为 `Set` 元素或 `Map` key 的对象必须正确实现二者。
- `ArrayList.subList` 的结果不得强转为 `ArrayList`。
- 使用 `subList` 时，不得在原集合上做会改变元素个数的操作，否则子列表遍历、增删会出错。
- 集合转数组必须使用 `toArray(T[] array)`，传入类型完全一致的数组。
- `Arrays.asList` 得到的集合不得调用修改集合结构的方法，如 `add`、`remove`、`clear`。
- 用 `<? extends T>` 接收的泛型集合不能调用 `add`，`null` 除外。
- 不要在 foreach 循环中直接 `remove` 或 `add` 元素；删除元素使用 `Iterator.remove`。
- `Comparator` 必须满足自反性、传递性、对称性，避免排序算法异常。

## 并发

- 获取单例对象必须保证线程安全，单例中的方法也要保证线程安全。
- 创建线程或线程池时必须指定有意义的线程名称。
- 线程资源必须通过线程池提供，不允许在应用中显式创建裸线程。
- 不允许使用 `Executors` 创建线程池，应通过 `ThreadPoolExecutor` 明确线程池参数。
- `SimpleDateFormat` 线程不安全，不能作为共享静态变量直接使用；必要时用锁、局部变量或线程隔离。
- 高并发同步调用必须考虑锁性能；能使用无锁数据结构时不使用锁，能锁代码块时不锁整个方法。
- 多资源同时加锁时必须保持一致加锁顺序，避免死锁。
- 并发修改同一记录时必须避免更新丢失，可在应用层、缓存层或数据库层加锁。
- 多线程并行定时任务不要使用 `Timer` 运行多个任务，单个未捕获异常会影响后续任务。

## 控制语句

- `switch` 中每个 `case` 要么通过 `break`、`return` 等终止，要么明确注释说明会继续执行到下一个 `case`。
- `if`、`else`、`for`、`while`、`do` 即使只有一行代码，也必须使用大括号。
- 如果使用连续 `if...else if...else` 表达复杂逻辑，最后必须有 `else`，并在其中处理兜底逻辑或错误。

## 注释

- 类、类属性、类方法注释使用 Javadoc 规范，即 `/** ... */`。
- 所有抽象方法和接口方法必须有 Javadoc 注释，说明参数、返回值、异常和方法职责。
- 所有类都必须添加创建者和创建日期。
- 方法内部单行注释另起一行写在被注释语句上方；多行注释使用 `/* ... */`，并与代码对齐。
- 所有枚举字段必须有注释，说明每个枚举项用途。

## 其他

- 使用正则表达式时，必须利用预编译能力提升匹配效率。
- Velocity 调用 POJO 属性时直接使用属性名，避免按 `getXxx` 写法误触发框架解析问题。
- 后台输出到页面的变量必须使用 `$!{var}` 形式。
- 使用 `Math.random()` 时必须注意返回范围是 `0 <= x < 1`。
- 获取当前毫秒数使用 `System.currentTimeMillis()`，不要使用 `new Date().getTime()`。
