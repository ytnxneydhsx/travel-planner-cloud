# 阿里 Java 异常日志强制规约

离线规则集：整理自《阿里巴巴 Java 开发手册》`1.3.0` 版的 `【强制】` 条款，并做了规约化转述。使用本 skill 不需要访问任何外部文件。

## 异常处理

- 对可以通过预检查规避的 `RuntimeException`，不得通过 catch 方式处理，应先做条件检查。
- 异常不得用于流程控制或条件控制。
- 不要对大段代码粗暴包裹 `try-catch`；应区分稳定代码和非稳定代码，只捕获必要范围。
- 捕获异常必须处理；如果当前层不处理，应继续抛出，不能静默丢弃。
- 事务代码中 catch 异常后，如果需要回滚事务，必须显式处理回滚。
- `finally` 必须关闭资源对象和流对象；关闭时出现异常也要捕获并处理。
- `finally` 中不得使用 `return`，避免吞掉 try/catch 中的返回或异常语义。
- 捕获异常类型必须和实际抛出类型匹配，或捕获其父类；不要捕获无关异常。

## 日志

- 应用中不得直接依赖 Log4j、Logback 等具体日志系统 API，应依赖日志门面，例如 SLF4J。
- 日志文件建议至少保存 15 天；如果项目有统一日志策略，应确认不低于该要求或说明差异。
- 扩展日志命名必须有清晰含义，便于监控和排查，例如访问日志、统计日志、临时监控日志等。
- `trace`、`debug`、`info` 级别日志必须使用条件输出或占位符方式，避免无谓字符串拼接。
- 避免重复打印日志；如使用 log4j，要关注 `additivity=false` 等配置。
- 异常日志必须同时包含现场信息和异常堆栈；如果当前层不处理异常，应继续向上抛出。
