# 阿里 Java 接口设计强制规约

离线规则集：整理自《阿里巴巴 Java 开发手册》`1.3.0` 版的 `【强制】` 条款，并做了规约化转述。使用本 skill 不需要访问任何外部文件。

## 命名与结构

- 所有命名不得以下划线或美元符号开头或结尾。
- 命名不得使用中文，不得使用拼音和英文混写；纯拼音也应避免。
- 类名使用 `UpperCamelCase`，但 `DO`、`BO`、`DTO`、`VO`、`AO` 等后缀保持全大写。
- 方法名、参数名、成员变量、局部变量使用 `lowerCamelCase`。
- 常量全大写，单词之间用下划线分隔，名称必须表达完整语义。
- 抽象类以 `Abstract` 或 `Base` 开头；异常类以 `Exception` 结尾；测试类以被测类名开头并以 `Test` 结尾。
- POJO 布尔属性不要加 `is` 前缀，避免框架序列化或反射解析错误。
- 包名全部小写，点分隔的每段只表达一个自然语义；包名使用单数形式。
- 禁止随意缩写，尤其是会造成望文不知义的缩写。

## 接口与分层

- 对 `Service` 和 `DAO`，对外暴露的服务必须先定义接口，内部实现类使用 `Impl` 后缀与接口区分。
- 已被外部调用或被二方库依赖的接口，不允许随意修改方法签名；必须评估兼容性和调用方影响。
- 序列化类新增属性时，不要修改 `serialVersionUID`；如果完全不兼容升级，才修改该值。

## POJO 与跨边界模型

- 所有 POJO 属性必须使用包装类型，不使用基本类型。
- RPC 方法参数和返回值必须使用包装类型。
- 定义 DO、DTO、VO 等 POJO 时，不要给属性设默认值。
- POJO 类必须实现 `toString`，如果继承其他 POJO，需要包含父类字段。

## 二方库契约

这些规则也会在 `alibaba-java-release-check` 中检查：

- GAV 坐标必须遵从命名规则：`GroupId` 使用反向域名，`ArtifactId` 使用产品线名、模块名等有语义名称，`Version` 表达主版本、次版本、修订号。
- 二方库版本号使用 `主版本号.次版本号.修订号`。
- 线上应用不要依赖 `SNAPSHOT` 版本，安全包例外。
- 二方库新增或升级时，除功能点所需变化外，其他 jar 仲裁结果不得随意变化。
- 二方库接口返回值不允许使用枚举类型，避免调用方因枚举变更出现序列化或兼容性问题。
- 依赖同一组二方库时，必须定义统一版本变量，避免版本不一致。
- 禁止在子项目 `pom` 中出现相同 `GroupId`、相同 `ArtifactId` 但不同 `Version` 的依赖声明。
